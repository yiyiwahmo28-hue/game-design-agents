# Contributing

Start with one small, original game-design problem. An issue should include
the intended player experience, relevant rules, what happened, and what you
expected. Use fictional examples or material you have permission to publish.

For a workflow change, show the input and the actual output it improves.
For a model or config change, run `npm test`, `npm run simulate`, and
`npm run verify`. Explain the behavioral tradeoff, not just the file diff.
For a visual change, include a screenshot of the running demo.

Keep the browser and simulator on the same model. Keep host-specific setup
outside the portable skill. A new role needs a distinct decision or handoff;
adding job titles alone does not improve the workflow.

Do not submit private project documents, real player data, internal links,
credentials, unlicensed assets, or confidential numerical tables.

This project currently has no measured agent-versus-agent benchmark. Label
illustrations, actual assistant runs, simulations, and human playtests accurately.
